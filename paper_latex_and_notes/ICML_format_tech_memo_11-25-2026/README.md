# Technical memo, 11-25-2026: cross-entropy, not correlation, for AI judges

**Doc link:** <https://github.com/brando90/judges-dont-need-psychometrics-or-corr/blob/main/paper_latex_and_notes/ICML_format_tech_memo_11-25-2026/README.md>

**TLDR:** One ICML-format memo that consolidates the results of every experiment folder in this repository (00 to 33, archived 11 to 14 included): a nine-page main text, references, then Appendices A to H with the proofs, a self-contained derivation that correlation sees one moment and cross-entropy sees all of them, the controlled studies in detail, the ranked probability score (RPS), the protocols, an index of all experiments, extra tables and figures, and provenance. `memo_11-25-2026.pdf` is the compiled memo. Every experiment result it reads was committed at or before commit `2bd73d9`. The memo is deposited in the Stanford Digital Repository at <https://purl.stanford.edu/pr787bn6444> (DOI 10.25740/pr787bn6444).

**Title:** Learn Judges Like Any Other Model: Cross-Entropy, Not Correlation, for Predicting Human Rating Distributions. Brando Miranda, Stanford University. 11-25-2026.

## Files

- `memo_11-25-2026.pdf`: compiled memo (ICML 2026 style, preprint option). Main text through the recommendations (pages 1 to 9), then references, then Appendices A to H.
- `memo_11-25-2026.tex`, `sections/`: LaTeX source. `01`–`08` are the main text; `A_proofs` (derivations and the exact counterexample), `B_moments` (first moment versus all moments, a self-contained derivation checked by experiment 33), `C_controlled` (the synthetic studies in detail: design, learning curves, rank objectives, optimizer budget, target complexity, why correlation is not the primary metric, and the retrospective forest plot), `D_rps` (the ranked probability score: definition, properness, worked examples, limits), `E_protocols` (metric definitions, protocols, how each judge was chosen), `F_index` (every experiment, its question and headline result), `G_extra` (details, tables and figures behind the main text), `H_provenance` (reproduction and data handling).
- `figures/`, `tables/`: generated by `make_memo_assets.py` from committed result files of experiments 02, 06, 07, 08, 24, 25, 26, 28, 29 and 31 and archived experiments 12, 13 and 14, the figure that experiment 08 printed for the AAAI paper folder, the exact rational arithmetic of the three-item counterexample (experiment 27), and the worked examples of `AAAI_2027_EvalAIScientists_JudgesKL/rps_appendix_examples.py`. The script recomputes the intervals of Appendix C from the per-seed results of experiments 06, 07, 08 and 13, so the last printed digit can differ from an experiment's own report. Nothing is typed by hand.
- `assets_log.txt`: the values the script printed for the figures and tables.
- `memo_refs.bib`, `icml2026.sty`, `icml2026.bst` and the helper style files: bibliography and ICML kit.
- `check_numbers.py`: a screening aid. For each memo line it collects the decimals and the integers of 100 or more (integers below 100 are not checked) and passes the line when one report file under `experiments/` or `paper_latex_and_notes/`, or `assets_log.txt`, holds all of them. It ignores the generated tables and the memo's own sources, and it checks that the numbers exist, not that the sentence draws the right conclusion from them. Lines it cannot match are listed for a manual check against the experiment folder; the last run listed three, and all three matched their experiment folders (a comma-separated ridge grid read as one number, and two counts in experiments 18 and 23).
- `HANDOFF_STANFORD_LIBRARY_11-25-2026.md` (in the repository only, not in the deposited archive): title, abstract, keywords, license, file hashes and the decisions for the deposit.

## Build and check

From this directory:

```bash
make                                   # python3 -I make_memo_assets.py, then latexmk -pdf (pdflatex + bibtex)
cd ../.. && python3 -I paper_latex_and_notes/ICML_format_tech_memo_11-25-2026/check_numbers.py
```

The build needs only committed files. It makes no model calls and costs nothing. Aux files are gitignored; the PDF is committed with any change to the source.

The standalone source archive (this folder without the repository) rebuilds the PDF with `make pdf`, using the figures and tables it contains. Regenerating those, and `check_numbers.py`, need the repository at the commit named above.

## How to read the numbers

Every reported number follows this repository's reporting rule: the data (train, validation or held-out test), the metric with its definition and direction, what a difference subtracts from what, the interval and how the judge was chosen. Differences are written as "test RPS of the Pearson-trained judge minus test RPS of the CE-trained judge; positive means the CE-trained judge is better". Appendix E states the metric definitions and protocols; each experiment folder has its own `HOW_TO_READ_RESULTS.md`.
