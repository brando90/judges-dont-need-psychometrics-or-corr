**TLDR:** An independent reviewer (Claude Opus at maximum effort, about fourteen minutes, CPU only) re-ran Cursor's Experiments 29 and 30 in `trustworthy-theorem-judges` (`experiments/29_refit_cumulative_logit_heads_ce_versus_rps_on_445_ratings_start_27Nov2026/` and `experiments/30_rank_next_human_ratings_by_judge_ensemble_uncertainty_and_power_curve_for_the_held_out_rps_gain_start_27Nov2026/`) from a fresh clone and recomputed the key numbers with its own code. The Experiment 29 headline, the 50-task nested head (normalized ranked probability score, RPS, 0.0684 against 0.1186 for the fold-wise set-aware constant; paired difference minus 0.0502, interval minus 0.0726 to minus 0.0290), is robust but exploratory: the earlier Experiment 28 (11-26) had already shown minus 0.0501 on the same 50 tasks, folds and ratings, and the preregistered 20-task primary is "not found". Experiment 30's forward simulation cannot fail by construction, and "23 tasks" is roughly the fifty-percent-power point. Nineteen findings are below.

## The findings in one line each (numbering follows the review)

1. **Blocking: Experiment 30's only documented command fails.** `scripts/run_analysis.py` line 191 uses `defaultdict` and never imports it (exit 1, `NameError`). The receipt records NumPy 1.26.4, so the committed results came from a script that is not the committed one. With the one-line import added, both priority CSVs are byte-identical and the JSON matches to about one part in a million.
2. **Blocking: Experiment 29's README sequence crashes, and its selection file was edited by hand.** `select()` writes a payload without `best_converged_primary` or `amendment_1`; `evaluate()` requires the first (line 236), so `--stage eval` fails with `KeyError` after the README's own `--stage select`. The committed selection JSON carries both keys. With the committed file restored, the evaluation and nested outputs are byte-identical.
3. **Important: "preregistered" and "written before" cannot be checked.** Both `PREREG.md` files first appear in the same commit as the results (5438370 and f76d502).
4. **Important: the 50-task "works" verdict repeats Experiment 28 and is secondary by the preregistration's own rule.** Experiment 28 already showed minus 0.0501 and minus 0.0483 on the same 50 tasks, folds, 445 ratings and constant (0.1186). The preregistered confirmatory verdict (20-task primary) is "not found", yet the README, `results.md` and the technical report put the nested result first.
5. **Important: the cross-entropy-versus-RPS comparison is confounded by the penalty.** The L2 term is added to the mean loss, and the RPS loss is about ten times smaller, so one penalty weighs about ten to twenty times more against RPS. With no penalty the RPS-fit head wins a majority of matched validation pairs; with any penalty from 0.1 up it almost never does. With no penalty the RPS objective has no finite minimizer.
6. **Important: "temperature 2" is a near-tie of one unconverged fit,** and the primary's test digits depend on the optimizer's 250-iteration limit.
7. **Important: the LaTeX gives the wrong reason for "not found".** It blames non-convergence; the rule fails because cross-entropy (1.249) is worse than the constant's (1.159).
8. **Important: Experiment 30's forward simulation cannot fail, and its general reason is false.** New ratings are drawn from each artifact's current histogram with the forecasts fixed, so the interval must return to the current one. A task bootstrap does shrink when real extra ratings remove rating noise; on these data rating noise is only about seven percent of the task-level variance, so the practical conclusion is plausible for a reason the experiment did not measure.
9. **Important: Experiment 30 is framed only around the F8 head,** while Experiment 29's primary and best converged heads already exclude zero on the same 20 tasks (F8's own bound is fragile: 4 of 20 single-task deletions flip it).
10. **Important: "23 tasks" is the fifty-percent-power point, not a target.** The reviewer's sensitivity analysis gives about 26 to 62 tasks for 50 to 90 percent power at the observed effect, more if the true effect is smaller. "Three more tasks, about 26 ratings" is the line most likely to be misquoted.
11. **Minor to important: the task-subsample sentence does not follow from its own number.** About one in five 6-to-18-task subsamples has an upper bound below zero, while the full 20 tasks does not.
12. **Minor: the active-versus-uniform five-rate comparison can barely differ** (only 106 extra ratings exist, both policies reveal 100 of the same 106).
13. **Minor: several Experiment 29 numbers are printed by no committed script** (the best-converged-minus-F8 contrast, the primary-minus-F8 contrast, the weight norms).
14. **Minor: a bootstrap fraction is labeled a p-value** (Experiment 30).
15. **Minor: the Experiment 29 README TLDR lacks the required reporting elements** (subtraction order in words, interval type, number of draws, direction of better, RPS and constant definitions, prior exposure of the 50 tasks).
16. **Minor: splits are by task only.** Raters and solver agents cross the splits, and neither document says so.
17. **Minor: code hygiene and weak tests** (a dead `verdict()` that would raise, a hard-coded 185/250, a silent attestation filter, tests that assert literals, no test of select-to-eval compatibility, which would have caught finding 2).
18. **Minor: hygiene.** The owner's personal Gmail address is committed in Experiment 30's `RESULTS.md` and `results.md`; those two files are byte-identical duplicates; `run_analysis.py` writes an uncommitted scratch folder.
19. **Minor: derivation precision** (the (n+1)(n+2) denominator is the shrinkage of 1/(n+1), not 1/n; the propriety remark conflates propriety with location sensitivity). No theorem is stated and nothing is machine-checked, so there is no Lean obligation.
