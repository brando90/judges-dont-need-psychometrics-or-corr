# SummEval expert grades and archived judge inputs | 11-21-2026

As of 11-21-2026, the adapter joins 1,600 summaries from 16 systems on 100 CNN/Daily Mail news articles. Every article has one summary from every system. The primary target is expert-rated factual consistency with the article. The separate sensitivity target is expert-rated relevance of the selected information. Each has three individual integer ratings per summary on a 1–5 scale, giving 4,800 observed ratings per dimension. The same graders assessed multiple dimensions in one assignment, so these dimensions do not represent separately purchased assignments. [Authors’ annotation release](https://storage.googleapis.com/sfr-summarization-repo-research/model_annotations.aligned.jsonl) · [SummEval paper, §4](https://aclanthology.org/2021.tacl-1.24/)

**Whose distribution is estimated?** The corpus also records five crowd-worker judgments per summary. The target here is the three-expert panel. The primary article documents an initial round plus a second-round review of large disagreements. Experts could see other experts’ first-round judgments when re-evaluating examples. Their final ratings can therefore be dependent. Each annotation dictionary contains the four criteria without a rater identity. This analysis holds out articles while reusing the panel and the 16 systems. [Collection description and two-round procedure, pp. 396–397](https://aclanthology.org/2021.tacl-1.24.pdf)

**Historical costs.** Fabbri et al. report a target average of US$12 per hour for the Amazon Mechanical Turk crowd workers. The paper supplies neither an expert hourly price nor a per-summary duration or price that would convert the target into a dollar cost per expert rating. The authors’ published repository also lists an unanswered question on total annotation spend. Reusing both public archives here required zero new paid human or model calls. [Paper, §4](https://aclanthology.org/2021.tacl-1.24/) · [Repository cost question](https://github.com/Yale-LILY/SummEval/issues/42)

## Two judge inputs

The **native G-Eval judge** is the empirical distribution of the released GPT-4 responses for the given criterion, conditional on a parseable grade. Each criterion has 20 saved samples per summary and 32,000 samples overall. These are sampled model ratings. The published paper reports GPT-4 temperature 1, top-p 1, and 20 completions. The pinned generator defaults to gpt-4-0613 and instead hard-codes temperature 2, top-p 1, a five-token response cap, and 20 completions. Across all 3,200 archived rows the raw records contain prompts and response texts but no request temperature, model ID or service response ID. The effective generation temperature and served snapshot therefore remain unknown. The paper and filenames identify GPT-4. The adapter reconstructs all 3,200 actual prompts from the article text, candidate and corresponding rubric. The metadata includes human score fields. The adapter excludes those fields from every judge input. G-Eval’s authors previously evaluated their rubric and methodology against SummEval; this is a historical benchmark replication. [G-Eval paper, §3.1](https://aclanthology.org/2023.emnlp-main.153.pdf#page=4) · [Pinned generator configuration](https://github.com/nlpyang/geval/blob/6f84404ce4503d2ba0cde0293c5d402ecf2976a8/gpt4_eval.py#L14-L42) · [Archived outputs](https://github.com/nlpyang/geval/tree/6f84404ce4503d2ba0cde0293c5d402ecf2976a8/results)

The fixed categorical parser accepts a first nonblank line containing just an integer from 1 to 5 or the explicit form n/5, with optional horizontal whitespace. It ignores subsequent explanation lines. The original G-Eval analysis extracted a leading number to calculate a scalar mean. Here an unparseable completion contributes only to the attempted count. Valid votes are normalized, with uniform fallback for zero valid votes. Consistency has 31,809/32,000 valid votes, with 1,419 summaries at 20 valid votes, 171 at 19 and 10 at 18. Relevance has 32,000/32,000 valid votes. All 1,600 rows per criterion remain; no item needed fallback. [Original scalar parser](https://github.com/nlpyang/geval/blob/6f84404ce4503d2ba0cde0293c5d402ecf2976a8/meta_eval_summeval.py#L29) · [Categorical adapter](prepare.py)

The **feature-based sensitivity judge** uses four fixed automatic scores released by the BARTScore authors. All 6,400 feature values are present and finite. ROUGE-2 F1 uses reference bigram overlap, ROUGE-L F1 uses reference longest-common-subsequence overlap, and BERTScore F1 uses reference contextual token similarity. The fourth score is unprompted BARTScore from source article to candidate using the pretrained facebook/bart-large checkpoint. These are available without the item’s expert ratings. The feature set excludes the human fields and the prompted or CNN/Daily Mail fine-tuned BARTScore variants. Metric choice and benchmark exposure can still affect generalization. The original SummEval repository’s updated metric-augmented Google Drive link returned HTTP 404. Its available annotation file supplies the raw human ratings; the separately pinned BARTScore release supplies the numeric metrics. [Published scoring data](https://github.com/neulab/BARTScore/tree/248f511cb34ae3753fc81f7d7a945de5bfe33458/SUM/SummEval) · [Scorer implementation](https://github.com/neulab/BARTScore/blob/248f511cb34ae3753fc81f7d7a945de5bfe33458/SUM/score.py) · [Report of missing original metric-augmented file](https://github.com/Yale-LILY/SummEval/issues/56)

## Identity, repeated text and file format

The adapter joins on source article ID and producer system ID. It verifies that every archive’s keys agree and that all BARTScore candidate texts match the SummEval candidates after lowercasing, normalizing Penn Treebank bracket markers and comparing the alphanumeric content. The G-Eval and BARTScore candidates match exactly on 1,528 rows; the remaining 72 match after reversing a UTF-8/Windows-1252 decoding discrepancy. The same reversible repair matches all 528 discrepant article-text occurrences, corresponding to 33 of the 100 articles. G-Eval received the original strings saved in its own requests. Its predictions remain as released. [Adapter checks](prepare.py)

There are 1,548 distinct exact candidate strings. Each of the 44 repeated strings occurred entirely within one article, accounting for 96 rows. After the more permissive normalization used for the cross-release candidate check, 72 repeated clusters contain 166 rows and zero clusters span articles. All producer outputs remain in the dataset, including duplicates for different systems. The BARTScore archive has 100 distinct article strings. These checks establish exact and normalized duplicate counts under the stated rules; overlapping stories or semantically equivalent texts can still occur.

Run the following from this directory. The adapter downloads only SHA-256-pinned public source files, reads the archived Python pickle using an allowlist for the two required NumPy scalar classes, and writes two compact NumPy files outside Git.

```sh
python3 prepare.py --cache /tmp/corr-ce-public-ordinal/summeval --output /tmp/corr-ce-public23
```

Each dimension’s file contains the same 1,600 rows sorted by (article ID, system ID) with string IDs and ordinary numeric arrays, readable with `allow_pickle=False`. The five target and forecast columns correspond in order to grades 1 through 5.

| Key | Contents |
|---|---|
| `X`, `features` | Raw 1,600 × 4 matrix and its column names, in order `rouge2_f`, `rougel_f`, `bert_score_f`, `bart_score_src_hypo` |
| `counts` | 1,600 × 5 integer expert-rating counts, row total 3 |
| `native`, `native_valid_votes` | 1,600 × 5 categorical G-Eval probabilities and 1,600 valid-vote counts out of 20 |
| `group`, `system`, `id` | Article grouping key, producer ID and unique article::producer item key |
